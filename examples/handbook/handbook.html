Team tools handbook

This handbook covers the tools the team runs every day: the sync agent, the command-line tool (CLI), and the desktop app. It is written for two audiences, new hires and engineers, and each audience gets its own voice of the same facts.

Support tiers

Every request to the platform team is assigned exactly one of three support tiers when it is opened:

  • Tier 1: the team responds within one business day. Covers outages and anything that blocks a release.
  • Tier 2: the team responds within three business days. Covers degraded behavior with a workaround.
  • Tier 3: the team responds within ten business days. Covers questions, requests for new features, and documentation gaps.

The tier is set by the person who triages the request, not by the person who opens it. A request can move between tiers once triage has looked at it.

How to read this handbook

Recommended. Read the setup guide first, then the data-handling policy. The policy is short and it is the one document everyone is expected to know.

The glossary in the reference section is kept as a table and is identical in every voice; it is the one place where wording never changes.

Guides / Setup

Setup

This guide takes a new machine from nothing to a working sync agent. Expect it to take about 20 minutes.

Install

  1. Install Node.js 22 or newer.
  2. Clone the tools repository and run npm ci in the repo root. Do not run npm install; it can change the lockfile.
  3. Start the agent:
tali-agent --port 8080

The agent prints ready when it is listening. If the port is taken, pass a different one with --port.

The CLI and the desktop app are different programs

The CLI reads its settings from ~/.tali/config.toml; the desktop app does not read that file and keeps its own settings in its preferences window. Changing one does not change the other.

Uploads from either program work only when the sync service is running. If an upload fails, check the agent first.

Verify

Recommended. Run tali-agent --check after setup. It exits 0 when the agent, the CLI, and the config file all agree.

  • Port 8080 is free or --port is set
  • ~/.tali/config.toml exists
  • tali-agent --check exits 0

Policy / Data-handling policy

Data-handling policy

This policy defines what may be sent to the hosted service and what stays on the local install.

What goes to the hosted service

Only public or fully synthetic data goes into the hosted service. Customer data, internal documents, and anything under a non-disclosure agreement stay on the local install.

Ask first. If you are unsure whether a dataset counts as public or fully synthetic data, ask the platform team before uploading. A Tier 3 request is the right channel for that question.

What the sync agent does and does not do

The sync agent reduces exposure but is not a sandbox. It strips file metadata and blocks uploads larger than 50 MB, and it does nothing to inspect the content of a file. The person uploading is responsible for the content.

Retention

The hosted service keeps uploaded files for 30 days, then deletes them. The local install keeps files until you delete them yourself. These two retention periods are independent: deleting a file locally does not delete the hosted copy, and the hosted copy expiring does not touch the local file.
