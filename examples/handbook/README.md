# Worked example: a three-document handbook in two voices

A complete, small tali project that the test suite builds and checks on every run. Copy it, replace the documents, and you have a working setup.

| Path | What it is |
| --- | --- |
| `docs/` | the source prose, where facts live |
| `voices/plain/` | the plain-voice copies, mirroring `docs/` file for file |
| `skeletons/` | one fact skeleton per source document (`fact-skeleton-template.md` format) |
| `voice-profile.md` | the plain voice, instantiated from the voice-profile template with a real fidelity list |
| `audiences.md` | the two audiences, instantiated from the audience template |
| `covers/overview-plain.md` | the plain voice's own cover, swapped in on its site version |
| `tali.fidelity.json` | fidelity-check config: sources, voices, skeletons, declared phrases |
| `tali.site.json`, `handbook.html` | publish config and page shell, both generated by `init_site.py` |

## Commands

From this directory, with `T` set to the tali `tools/` directory (`${CLAUDE_PLUGIN_ROOT}/tools` inside a session):

```
python $T/check_fidelity.py                 # PASS: 3/3 voice copies carry every fidelity item
python $T/check_tells.py voices/plain       # PASS: 0 strip, N review
python $T/build_page.py --check             # what build_page would regenerate
python $T/build_page.py                     # refill handbook.html from docs/
python $T/build_site.py                     # site/index.html (original) + site/plain.html
python $T/build_pdf.py                      # handbook.pdf, needs Chrome or Edge
python $T/build_pdf.py --page site/plain.html --pdf handbook-plain.pdf
```

The scaffold that produced the page and the site config:

```
python $T/init_site.py --sources docs --title "Team tools handbook" --subtitle "example" --voices plain
```

## What to look at

- `docs/policy/data-handling.md` against `voices/plain/policy/data-handling.md`: the prose loosens, the phrase `public or fully synthetic data` and the qualifier `reduces exposure but is not a sandbox` do not.
- `skeletons/policy/data-handling.skeleton.md`: which items the checker enforces (Verbatim, Labels, Fixed phrases, Qualifiers) and which a verifier judges (Claims, Distinctions).
- Change one word of a qualifier in a plain copy and rerun `check_fidelity.py`: it exits 1 and names the item.
- Matching is case-sensitive, because labels are. Declare a qualifier without its sentence-initial article (`desktop app does not read that file`, not `the desktop app ...`) so a copy that opens a sentence with it still matches.
